## 背景

作者已定计划：把 Nous-Slaveholder 开发为**通用监工工具**（不经 Farm 的独立 AFK 场景直接可用），未来以插件 / 契约后端身份接入 Farm。这与 ADR-0004 的一处否决正面冲突：

> ADR-0004「考虑过的替代方案」：**委托 Sentry/Slaveholder 管 agent 进程**——被否：Sentry 自己声明不做执行编排，Slaveholder 零代码；委托会把活性真相源推出 Farm，观测面分裂（与 ADR 0001 否决 Crossline 当 agent-runner 同一理由）。

翻案的两条新事实：①「零代码」前提即将不成立——Slaveholder 正在开发；②「观测面分裂」在契约模式下有解——Orchestrator 先例：外部进程走契约、同 claim、事件统一回流。

但真正要裁的不是「Slaveholder 好不好」。agent-runner 早就带着「可插后端」（GLOSSARY：本地后端 + 远程后端），悬着的是四问：第三类后端填不填、以什么身份填；#16 的判据阶梯要不要藏在可替换接口后面；双实现怎么防漂移；事件词汇谁映射谁、映射表落哪边。**有时间窗**：#16 被 #14/#15 阻塞尚未开写，此刻修订其验收措辞成本为零，落地后再改就是重构。

本票只裁接缝形状。插件 / 后端的**具体集成设计**（传输形态、ABI、载荷）仍等 #11 合入 + #26 契约冻结，触发条件与 Orchestrator 开图相同；本票不抢在冻结前设计插件本体。

## 决策

### 一、接缝成立，名它为「可插后端位」；监督者不是插件（必答 1）

**三类后端是同一 seam 上的可替换实现**，契约面对后端不透明：

| 后端 | 谁持有 agent 进程树 | 谁持有判据阶梯 |
|---|---|---|
| 本地后端 | Farm（spawn `pi --mode rpc`） | Farm（farm-core 里的 Rust 实现） |
| 远程后端 | 对端机器（Crossline 芯片） | 对端（Farm 只映射其事件） |
| **委托后端** | **本机的一个外部监督者进程** | **该监督者** |

「第三后端是否存在」与「那个后端现在是否实现完」是两个问题——接缝形状**现在**裁，不等 Slaveholder 有代码。Crossline 远程后端早在 ADR-0001 就留了位，彼时它也没有代码。

**监督者进后端位，不进插件骨架。** 进程级 IPC 插件（#19 骨架语义：宿主子进程、消费事件、不驱动循环、无状态 tick 循环）装不下监督者——监督的本质是**持有生命周期**，这正是 backend 的语义。更硬的理由：若把它当插件，插件监督策略（分级退避重试 + 隔离）与判据阶梯（两口钟 + abort 探针）会变成两套生命周期管同一个进程，而 ADR-0004 裁决 4 末句明令「pi 子进程不是插件，不进插件重试策略」——同一条界线在缝上要继续成立。把插件契约扩成「可派发插件」是另一张更大的票且方向可疑，本票不开。

**契约面只有五件事**：dispatch / steer / abort / 事件回流 / token 记账。判据阶梯、两口钟、读循环健康度、abort 探针、fork 找回**全是后端内部机制**，其出口只有映射后的事件。这一条是全部后续裁决的地基。

### 二、翻案的精确范围：推翻两个理由，维持裁决 1 的内核

ADR-0004 那条否决由**两个理由**和一个**内核**组成，本 ADR 分别处理：

- **推翻理由一「Slaveholder 零代码」**——前提已败，作者在建。该理由随实现推进自然失效。
- **推翻理由二「委托会把活性真相源推出 Farm，观测面分裂」**——契约模式下不分裂：外部进程只做事件生产者，经映射表汇入 Farm 事件总线（Orchestrator 先例；远程后端 #28 的 Crossline 11 事件闭集映射同一形状）。分裂只发生在**无映射表、无统一回流**时；那是实现缺失，不是委托的必然。
- **维持 ADR-0004 裁决 1 的内核「agent-runner 自 spawn、自监督」**——作为**本地后端**的属性不动。三条理由：
  1. 单二进制部署（ADR-0003）不许 Farm 的主路径依赖一个外部二进制；`cargo-dist` 出的单文件机器上未必有 Slaveholder。
  2. Slaveholder 的判据数值**零运行时实测**（其 #24 未跑），且两仓 pi 版本偏斜是既成事实（Farm 基准 1.0.2，Slaveholder 钉 0.84.3）。`docs/research/report-nous-family.md:319` 已裁「Farm 只能借结构，不能借数值」。
  3. 本地后端自持一份实现，是「规格单一源 + 双实现 + 一致性套件互认」的前提；把它整个委托掉，这个前提就没了。

所以本 ADR 的裁决**不是**「Farm 把阶梯委托出去」，而是「**Farm 自持一份 Rust 实现，并承认别处依法可以有第二份**」。ADR-0004 那条否决的措辞已在原文件加修订注记（见该文末）。

**ADR-0004 裁决 1 那句原话的精确修正**：「Slaveholder 仓本身不进 Farm——它的 ADR 是规格，不是依赖」⇒ 「Slaveholder 仓**不作为依赖**进 Farm；作为可替换后端经 adapter 接入」。原句的「不是依赖」四字在本 ADR 之后**依然成立**——被推翻的是把它读成「永远不能出现在 Farm 的任何位置」。

### 三、规格单一源与双实现互认（必答 3）

- **规格单一源 = Slaveholder 的判据学 ADR（0001–0006），且只到结构层**：两口钟分工、五级次序、读循环健康度前置、abort 探针独立死线、完成双条件、三列不成一态、终态是事件而非状态、`crashed.reason` 封闭枚举（八值 + `spawn_failed` = 九值）。
- **规格按 pi 版本参数化**：`stopReason` 白名单、`agent_settled` 语义、`gate_failed` 触发差异都随版本变，故规格母本写成「判据结构 + 版本差异表」的形式；差异表即 Farm 侧「换 pi 版本必重读清单」的输入。Farm 侧引用规格时必须随附 `runtimeKey`（裁决五）。
- **数值权威不在单一源里**：`T_model` / `T_tool` / `C_rung` / k 系数 / 30s 死线等常量，在 Slaveholder 24a（fake pi 场景集）与 24b（真派对账）出数之前，双方一律按「**候选默认值 + 各自复测**」对待。参数化不等于把未实测的数冻结成规格——那是两仓共同的成文纪律，不是单边的。
- **双实现的互认凭证是三件物**：
  1. **fake pi 场景集**——JSONL 脚本进、断言出，零凭据、可重放。场景表与 Slaveholder #24a 的 S1–S5 对齐成一张表（正常 settle 双条件、静默钟、总钟、abort 探针死线、fork 找回、token 流式记账含 `parentToolCallId` 嵌套用量、中断快照 + 长 bash 无输出 / 有输出 / 回合间隙 / 压缩期 / abort wedge）。**一份资产两用**：既校准 Slaveholder 的数值，又当 Farm #16 的 pi 子进程 seam。
  2. **一致性套件**——同一份断言跑两个实现（farm-core 本地后端 + Slaveholder 实现）。沿用 Crossline 纪律：一致性套件是「给重写发通行证」的机构，跑不过 = 该实现不符合规格，不是规格歧义。
  3. **接口快照**（裁决五）。
- **场景集的迁徙方向**：#16 开工时即以**独立场景文件**（非内嵌 Rust 测试）写在 Farm 侧；落成后上缴 Slaveholder 仓作单一源，两仓 CI 各自跑同一套。**不共享可执行资产的「语义互认」不算互认。**
- **漂移的仲裁者是一致性套件，不是任何一仓的文档。** 双实现因此从「风险」变成「规格可被证伪的机制」——单实现反而无从证伪。

### 四、缝契约的七件固定件

无论第几类后端，以下七件是接缝的固定内容（本票只定形状，具体载荷归契约冻结）：

1. **契约面对后端不透明**：dispatch / steer / abort / 事件回流 / token 记账，无第六件。
2. **attempt 记录带三个后端字段**：后端标识、**阶梯归属**（自持 / 外持）、`runtimeKey`。阶梯归属是显式具名属性，不是隐藏假设——它是本地后端与委托后端的唯一实质分别。
3. **事件映射表**，方向见裁决五。
4. **后端健康与 attempt 活性分离**，见裁决五。
5. **`run_id` 由 Farm 签发**：Farm 拥有 attempt、是编排侧身份，故由它生成并作为跨缝关联键交给监督者；监督者用它自己的派 identity 做自己的键。这解掉 Slaveholder 侧「我们没有 `run_id`」的问题（其 #25 腿功 §2.3 Q2）。
6. **粒度 1:1**：一个 Farm attempt = 一个被监督的进程树。监督者的「换派重来」（三级手段之一）在缝上是**一个新 attempt**，不是 attempt 内部细节。若未来要内部换派而不新 attempt，那是缝的**加法扩展**（schema 加法，不 bump 版本），不是 v1 语义。
7. **一致性套件的断言与后端无关**：同一份断言在结构上可跑在多个传输绑定上（#28 已承诺「同一份断言、两个传输绑定」）。

### 五、事件词汇与版本：Farm 词汇是目标，偏斜显式进缝（必答 4）

- **映射方向：监督者词汇是源，Farm 词汇是目标。** 理由不是谁强势，是观测面在哪收口——面板唯一读源是 Farm SQLite（ADR-0005 裁决 1/2），Kron 是审计真源，面板永不读监督者。
- **映射表住缝契约，两仓各存一份**，靠同一份 fake pi 场景集 + 跨仓漂移测试保持一致（= Slaveholder #25 腿功 §2.1 Q1 的选项 iii）。
  - 这里要与「Slaveholder 保持零 Farm 知识」划清：那条指的是**依赖箭头单向**（Slaveholder 不链 farm-sdk、不 import Farm 代码），本裁决不动它——**测试资产不是依赖**。Slaveholder 仓存一份映射表作为它自己的符合性期望，不等于它有了 Farm 依赖。
  - 单边存储被否：单边可改即无可证漂移，且裁决三要求的「同一份断言跑两个实现」在词汇轴上就没有共同对象了。
- **现在就定的几条映射**（其余全表归契约冻结）：

  | 监督者侧 | Farm 侧 | 说明 |
  |---|---|---|
  | 三列（活性 / 进展 / 判据） | attempt 上三个具名字段 | **永不合并成一个 `status`**——Slaveholder ADR 0006 裁决一的理由（三者会不一致，而不一致本身是最该记的事实）在 Farm 侧同样成立 |
  | `judgement_face_unavailable` | 一等事件 `needs_attention` | **不进 stall 判杀**。这是 ADR-0004 勘误同族的铁律：判据面自己瞎了必须从外部看得见，不能与「照常放行」混淆 |
  | `judgement{stuck}` | attempt 内中间记录 | **不升一等事件**。stuck 是阶梯内的可恢复态，不是终局 |
  | `crashed{reason: ladder_exhausted}` | stall 判杀 | 唯一升 stall 判杀的路径：一等事件 + Kron 双写 + `needs_attention` |
  | `reaped` | attempt 成功 | 前提是完成双条件的两个分量都能过缝被证明（`agent_settled` + 末条权威 assistant `stopReason === "stop"`） |
  | `crashed{stream_closed}` | attempt `interrupted`（`accounting_truncated`） | 与 Farm 自产的 `interrupted`（宿主重启，ADR-0005 裁决 4/11）是**同一会计语义的两个来路**：都不触发退避计数，都标 `accounting_truncated` |
  | `crashed{silence_exhausted / total_clock_exhausted / abort_unresponsive}` | attempt 失败 + 一等事件 | 按 Farm 现有失败语义 |
  | `crashed{spawn_failed}` | spawn 失败 | 取凭据失败同路（ADR-0004 裁决 3：走 `needs_attention`） |

- **活性列过缝但改姓**：不作 attempt 的活性真相源，作**后端健康**信号。attempt 活性仍由 Farm 自己的观测推导；外部监督者只报它自己的死活。监督者死 ⇒ 它名下的 attempt 全部转 `interrupted`（派陪葬，Slaveholder ADR 0003/0006 同结论）。
- **`runtimeKey` 进缝，作版本窗校验**：backend 声明 `runtime_key`；派发期校验，**窗外 = Loud 拒绝**——闭集错误码回调用方，人话点名双方版本与「换 pi 版本必重读清单」，不是静默跑一套没重读过的判据语义。窗内 = 记录 + 放行，值落 attempt 且进事件。
  - 这是**监督窗**，不是版本法令：ADR-0004 裁决 5「pi 版本归配方钉，Farm 不越权」不变——Farm 不裁定派跑哪个版本，只拒绝监督它没验证过判据语义的版本，并把拒绝说出口。形态同 Crossline 协议窗（#28：窗外 Loud 拒绝、断连 + 点名双方版本与修法）。
  - 窗外拒绝是**派发期**事件（同步回调用方），不是 attempt 内异常；是否同时发 `needs_attention` 归契约冻结。
  - 必须是**现抓值**不是配置值：「装的是哪个版本」≠「实际跑的是哪个版本」。
- **接口快照**：两仓共同锁定一份「pi 版本 × RPC 命令集 × 事件集」的具名清单。**本轮已发现一处实证漂移**：同称 pi 1.0.2，Slaveholder #18/#25 腿功记 **33 命令 / 24 事件**，Farm `docs/research/pi-runtime-interface.md` 与 spec L97 记 **34 命令 / 22 事件**。没有共同锁定的快照，「测试互认」没有共同对象。快照归 #26 契约冻结的输入，不归本票。
- **版本偏斜的处置**：不是裁谁对，是显式进缝。本地后端与委托后端可以跑不同 pi 版本，`runtimeKey` 让差异在 attempt 上可读；「换 pi 版本必重读清单」随缝维护，两边各持一份、以快照对齐。Slaveholder 的 pin 退为它自带蓝图镜像的默认值，不越权管 Farm 的配方钉（ADR-0004 裁决 5 不变）。

### 六、Kron 双写分工

- **分工两笔，不同事件，各写各的**：Farm 写编排决策（派发 / merge / 审批 / stall 判杀 / `host_restarted`），`actor=farm`；监督者写派生命周期（spawn / settled / crashed / reaped），`actor=slaveholder`。**同一事件不两笔**——避免幂等键撞击与双份噪音。
- **无新跨仓协调义务**：`slaveholder` 位本就在 Kron 的 actor 写入方闭集里（实测 `internal/schema/schema.go:55`）；`farm` 扩位已完成（Kron ADR 0013 / ledger 0.2.0，见 #19 票面）。
- **台账 vs 账的分界不变**：监督者的 JSONL 事件流仍是它自己的台账真相层，Kron 是账。Farm 不从监督者拉事件再转写 Kron——各写各的，读侧都只读自己的。

### 七、#16 验收措辞立即回写（必答 2）

时间窗内完成，成本为零。接缝对 #16 的全部要求是**四条「不要焊死」**，不是「提前实现第三后端」：

1. **判据阶梯住本地后端内部，不进契约面**：阶梯的内部词汇（静默钟 / 总钟 / 读循环健康度 / `judgement_face_unavailable` 等）不得作为契约字段或 attempt 状态名出现，只能以映射后的事件形态过缝。
2. **attempt 存储形状留三个后端字段位**（后端标识 / 阶梯归属 / `runtimeKey`）；不要求三种后端的实现都在 #16 里。
3. **fake pi 场景集按可移植格式写**：独立场景文件、非内嵌 Rust 测试；场景表与 Slaveholder #24a 的 S1–S5 对齐成一张表。
4. **一致性套件断言写成与后端无关**：不得写出只有本地后端能过的断言（#28 的「同一份断言、两个绑定」由此获得前提）。

**#16 不实现委托后端。** 委托后端不进 #16 范围。

### 八、槽位开放，开票设两道门

委托后端槽位**在文档与 #16 的接口形状里现在开放**，但开票要过两道门：

1. **#11 合入 + #26 契约冻结**——与 Orchestrator 开图同一触发条件；插件本体不提前设计。
2. **接口快照两仓共同锁定**（裁决五）——没有共同对象就没有互认。

两道门之前：不开票、不写实现、不设计 ABI。Slaveholder 侧 #25 腿功提议的条件新票「契约后端面：Slaveholder 作为 Farm agent-runner 第三后端」，其 Farm 侧前提已满足一半（#27 已裁），剩 #26 冻结 + 接口快照；该票另受 Slaveholder #12（CLI 机器面）阻塞。

## 死因分析（ADR-0004 那条否决错在哪，哪部分还活着）

- **死的是「零代码」前提**——事实变更，不是推理错误。
- **「观测面分裂」被契约模式推翻，但其内核仍活**：分裂的真正条件是「**真相源推出 Farm**」，不是「**进程是别人的**」。将来引用「观测面分裂」否决别的东西时，必须按这个条件检验，而不是按「进程归属」检验——否则会连远程后端一起否掉。
- **裁决 1「自 spawn、自监督」活得最全**：本 ADR 把它从「Farm 唯一形态」收窄为「本地后端的属性」，理由一条没删，只是不再外延到全部后端。

## 考虑过的替代方案

- **维持边界：Slaveholder 只做独立工具，Farm 自持判据阶梯，不设第三槽位**——被否：代价是 #16 落地后加槽即重构（时间窗论点），且与作者已定的「Slaveholder 通用工具化、未来以契约后端身份接入」计划正面冲突；「观测面分裂」在契约模式下已有解（远程后端先例），不构成否决理由。即便裁维持边界，裁决三/五的词汇与映射问题依然要为 #28 全部回答一遍——那条路上这些答案省不掉。
- **三种后端各一个 seam**——被否：契约面立刻三份，面板与编排器要写三套观测，#28 承诺的「同一份断言、两个绑定」被破坏；Crossline ADR-0010 的一致性套件纪律正是禁这个的。
- **委托后端做成进程级 IPC 插件（进 #19 骨架）**——被否：插件骨架语义是「消费事件、不驱动循环」的无状态 tick；监督者持有 agent 生命周期。装进插件骨架会让两套生命周期管同一个进程，冲垮 ADR-0004 裁决 4 末句的界线。
- **本地后端也委托给 Slaveholder（Farm 完全不自持阶梯）**——被否：单二进制部署不许主路径依赖外部二进制；Slaveholder 数值零实测且两仓 pi 版本偏斜；这把 ADR-0004 裁决 1 的整个内核推翻，超出本票授权。
- **映射表只存一边（Farm 适配 Slaveholder，或 Slaveholder 适配 Farm）**——被否：单边存储 = 单边可改，漂移无可证；且「同一份断言跑两个实现」在词汇轴上失去共同对象。双列同源 + 跨仓漂移测试是唯一可证形态。
- **`stuck` 1:1 映射到 Farm stall 判杀**——被否：stuck 是阶梯内可恢复的中间态，1:1 会让每次静默钟响都发一等事件 + 双写 Kron，把 `needs_attention` 稀释成噪音，真终局反被淹没。
- **`interrupted` 只由宿主重启产生**——被否：委托后端下监督者流断（派陪葬）是同族会计事实，标 `failed` 会错记一次本可恢复的中断，并错误触发退避计数。
- **runtimeKey 失配即静默硬失败（只回个错误码，不点名版本、不提重读清单）**——被否：静默拒绝正是本 ADR 要拆掉的那个模式；窗外必须 Loud。已改为版本窗 + Loud 拒绝（裁决五）。
- **等 Slaveholder 有代码再裁 seam**——被否：#16 的措辞时间窗在彼时已关，落地后再改就是重构。
- **另立第三份规格文档当单一源**——被否：官僚发明，无维护主体。

## 后果

- #16 验收措辞已回写（裁决七），时间窗内完成。
- #28 的「后端 seam 形状」阻塞**解除**（三种后端同一 seam 已裁）；#28 仍 blocked by #16——本地后端的判据与记账口径要先立住，远程后端复用之。
- Slaveholder 侧条件新票的 Farm 侧前提满足一半；剩 #26 契约冻结 + 接口快照。
- 场景集迁徙（Farm → Slaveholder 仓）是 #26 一致性套件整备的前置之一。
- GLOSSARY 新增五条：可插后端位、委托后端、后端健康、runtimeKey、接口快照；Agent-Runner 与判据阶梯两条加接缝措辞。
- ADR-0004 替代方案一节加修订注记，显式记录翻案范围（不静默覆盖）。
- Kron 侧无新协调义务。
- 未决（不阻塞开工）：事件映射表全表、委托后端的传输形态（子进程 CLI / 管道 / 契约接口）、窗外拒绝是否兼发 `needs_attention`、Slaveholder 判据数值 24a/24b、1.0.2 接口面计数两仓不一致的最终锁定值。
